## Current blockers and limitations

1. No portable organizer/provider API key and model ID is available. The
   existing local ChatGPT login successfully powered the judged browser flow,
   but it is account-dependent and intentionally not copied into the repo or a
   container. A judge-reproducible hosted/provider-key deployment remains
   unproved.
2. Docker, Colima, and Podman remain unavailable. The relay launcher uses the
   existing local-process Runtime; the organizer's disposable container path
   is still not reproduced locally.
3. The verified local JetStream topology is one file-backed process. It
   survives process restart but not disk or machine loss; a multi-node cluster
   has not been reproduced.
4. Immediate SSE notification is in-process, with a five-second durable-state
   resynchronization fallback. Cross-instance live fan-out behind a load
   balancer has not been reproduced.
5. The imported starter initially reported six dependency advisories. A
   non-forced `npm audit fix` changed seven packages within the declared
   semver ranges; `npm audit --audit-level=moderate` now reports zero known
   vulnerabilities and the complete test/build gate still passes.
6. A registry-matching macOS `@openai/codex@0.111.0` platform binary was
   blocked by macOS as malware and moved to Bin on first execution. The warning
   was not bypassed and the remaining ignored probe directory was deleted.
   Source inspection remains possible, but this binary is not considered a
   usable or reproduced local Runtime.
7. The safe bundled CLI is an installed, auto-updatable local artifact rather
   than the starter-pinned version. Its current signature, version, hash, real
   model output, JSON event parsing, thread persistence, and Relay compatibility
   are recorded; version/signature/login must still be rechecked before
   recording or judging.
8. The reproduced coordinator consumes one turn at a time. It proves ordered
   handoffs but not high-throughput parallel scheduling; one long Run can delay
   other local sessions.
9. Agent workspaces and Codex thread IDs remain per-Agent and persistent across
   sessions. The relay transfers the saved textual artifact and review contract;
   it does not provide a transactionally shared code workspace or automatic
   isolation from an Agent's earlier task context.
10. Session histories retain accepted outputs and cap the visible event list at
    500 events, but long-term stream/KV retention and near-limit multi-megabyte
    artifacts have not been load-tested.
11. Bouncer version 1 recognizes a deliberately narrow set of direct deletion
    patterns. It does not cover arbitrary scripts, obfuscated shell, overwrite,
    network side effects, or every Codex tool path, and it is not an OS sandbox.
12. Kill Switch signals the tracked Codex CLI, not an OS/container process
    group. The verified loop exited, but arbitrary detached descendants may
    survive; completed side effects are not rolled back.
13. Shared-workspace coordination is deliberately sequential. This prevents
    competing writes but does not demonstrate parallel Agent execution, and
    automatic assignment is availability/rotation based rather than semantic
    skill matching.

## 2026-08-31 adaptive control-plane update

The primary flow is now conversation-first and adaptive. A real planning Run
chooses 1–8 fresh task-specific workers, records why that number is sufficient,
defines evidence-bearing checkpoints, and never reuses a saved Agent without
explicit consent. The older separate workflow composer is not part of the
primary experience. Coordinated Runs use private per-Run workspace copies;
accepted checkpoints are promoted, while failed, killed, timed-out, or
restart-abandoned copies are discarded.

browser attestation. After an accepted checkpoint it serves the static result
over temporary localhost HTTP, opens Chrome at 375x812 and 1440x900, records
browser/page errors and horizontal overflow, takes screenshots, and stores
their SHA-256 hashes. The next worker receives this evidence. The first
`file://` implementation failed on module CORS and is not claimed; the corrected
HTTP path passed four times in live session
